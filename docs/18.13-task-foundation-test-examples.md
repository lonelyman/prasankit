# Task Foundation Test Examples

Task API ทุกเส้นในชุดนี้ต้องมี:

- `prasankit_session` cookie จาก login
- header `X-Workspace-Slug`
- backend resolve `tenant_id` จาก Tenant Context เท่านั้น
- request body และ response ห้ามใช้ `tenant_id`

## List Tasks

Endpoint:

```text
GET /api/v1/workspace/projects/{project_id}/tasks?page=1&limit=10
```

Query filters:

```text
status=todo|in_progress|blocked|done|cancelled
priority=low|medium|high
assignee_member_id=project-member-uuid
```

Success:

```json
{
  "data": {
    "items": [
      {
        "id": "task-uuid",
        "project_id": "project-uuid",
        "no": "TASK-0001",
        "title": "Prepare proposal",
        "status": "todo",
        "priority": "medium"
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 10,
      "total": 1,
      "total_pages": 1,
      "has_more": false
    }
  }
}
```

หมายเหตุ:

- ตอนนี้ list เฉพาะ tasks ที่ยังไม่ soft delete
- filter ทุกตัว optional และทำงานร่วมกันได้
- ต้องมี permission `workspace.view`

## Create Task

Endpoint:

```text
POST /api/v1/workspace/projects/{project_id}/tasks
```

Body:

```json
{
  "title": "Prepare proposal",
  "priority": "high",
  "assignee_member_id": "project-member-uuid",
  "description": "Draft proposal for review",
  "start_date": "2026-05-01",
  "due_date": "2026-05-07"
}
```

Success:

```json
{
  "data": {
    "id": "task-uuid",
    "project_id": "project-uuid",
    "no": "TASK-0001",
    "title": "Prepare proposal",
    "status": "todo",
    "priority": "high",
    "assignee_member_id": "project-member-uuid",
    "description": "Draft proposal for review",
    "start_date": "2026-05-01",
    "due_date": "2026-05-07"
  }
}
```

หมายเหตุ:

- `priority` ถ้าไม่ส่ง จะ default เป็น `medium`
- `assignee_member_id` ถ้าส่ง ต้องเป็น active project member ใน project เดียวกัน
- `no` generate จาก `task_counters` ใน transaction
- ต้องมี permission `workspace.manage`

## Get Task

Endpoint:

```text
GET /api/v1/workspace/projects/{project_id}/tasks/{task_id}
```

Success:

```json
{
  "data": {
    "id": "task-uuid",
    "project_id": "project-uuid",
    "no": "TASK-0001",
    "title": "Prepare proposal",
    "status": "todo",
    "priority": "high"
  }
}
```

หมายเหตุ:

- backend query ด้วย `tenant_id` จาก Tenant Context, `workspace_id` จาก Tenant Context, `project_id` จาก path และ `task_id` จาก path
- ต้องมี permission `workspace.view`

## Update Task

Endpoint:

```text
PATCH /api/v1/workspace/projects/{project_id}/tasks/{task_id}
```

Body:

```json
{
  "title": "Prepare proposal v2",
  "priority": "medium",
  "assignee_member_id": "",
  "description": "Updated proposal scope",
  "start_date": "2026-05-02",
  "due_date": "2026-05-09"
}
```

Success:

```json
{
  "data": {
    "id": "task-uuid",
    "project_id": "project-uuid",
    "no": "TASK-0001",
    "title": "Prepare proposal v2",
    "status": "todo",
    "priority": "medium",
    "description": "Updated proposal scope",
    "start_date": "2026-05-02",
    "due_date": "2026-05-09"
  }
}
```

หมายเหตุ:

- PATCH รองรับ `title`, `priority`, `assignee_member_id`, `description`, `start_date`, `due_date`
- ส่ง `assignee_member_id: ""` เพื่อ clear assignee
- ส่ง `start_date: ""` หรือ `due_date: ""` เพื่อ clear วันที่
- ยังไม่เปลี่ยน `status` ผ่าน PATCH; ให้ใช้ status endpoint แยก
- ต้องมี permission `workspace.manage`

## Update Task Status

Endpoint:

```text
PATCH /api/v1/workspace/projects/{project_id}/tasks/{task_id}/status
```

Body:

```json
{
  "status": "in_progress"
}
```

Success:

```json
{
  "data": {
    "id": "task-uuid",
    "project_id": "project-uuid",
    "no": "TASK-0001",
    "title": "Prepare proposal v2",
    "status": "in_progress",
    "priority": "medium"
  }
}
```

Allowed status:

```text
todo
in_progress
blocked
done
cancelled
```

หมายเหตุ:

- ถ้าเปลี่ยนเป็น `done` backend จะตั้ง `completed_date` เป็นวันที่ปัจจุบัน
- ถ้าเปลี่ยนออกจาก `done` backend จะ clear `completed_date`
- ต้องมี permission `workspace.manage`

## Delete Task

Endpoint:

```text
DELETE /api/v1/workspace/projects/{project_id}/tasks/{task_id}
```

Success:

```text
204 No Content
```

หมายเหตุ:

- เป็น soft delete: ตั้ง `deleted_at` และ `deleted_by`
- list/get จะไม่คืน task ที่ถูก soft delete แล้ว
- ต้องมี permission `workspace.manage`

## Common Errors

Invalid project id:

```json
{
  "error": {
    "code": "PROJECT_ID_INVALID",
    "message": "Project id is invalid"
  }
}
```

Invalid task id:

```json
{
  "error": {
    "code": "TASK_ID_INVALID",
    "message": "Task id is invalid"
  }
}
```

Task title required:

```json
{
  "error": {
    "code": "TASK_TITLE_REQUIRED",
    "message": "Task title is required"
  }
}
```

Task update has no fields:

```json
{
  "error": {
    "code": "TASK_UPDATE_NO_FIELDS",
    "message": "Task update has no fields"
  }
}
```

Invalid status:

```json
{
  "error": {
    "code": "TASK_STATUS_INVALID",
    "message": "Task status is invalid"
  }
}
```

Invalid priority:

```json
{
  "error": {
    "code": "TASK_PRIORITY_INVALID",
    "message": "Task priority is invalid"
  }
```

Assignee not found:
