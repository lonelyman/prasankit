## Locked Decisions

- Backend folder: `app-api/`
- Frontend folder: `app-web/`
- Git remote: `https://github.com/lonelyman/prasankit.git`
- Working branch: `dev`; merge into `main` manually after review/protection checks
- Backend stack: Go + Fiber v3
- Auth strategy: Session-based Auth + Redis + httpOnly Cookie
- Primary key strategy: UUID v7 generated by Go application
- API prefix: `/api/v1`
- Response success root key: `data`
- Response error root key: `error`
- Workspace API ห้ามใส่ `tenant_id` ใน URL
- `tenant_id` ต้องมาจาก backend Tenant Context เท่านั้น
- Reverse proxy: Traefik
- Run through Docker Compose เป็นหลัก

## Current Notes

- Local machine มี Go 1.23.5
- Dockerfile ใช้ Go 1.25 เพราะ Fiber v3 ต้องใช้ Go 1.25+
- Baseline ระยะยาวยังสามารถขยับเป็น Go 1.26.x ได้ภายหลัง
- Host ports ใน `.env.example` ถูกปรับเพื่อเลี่ยงชนกับ service ในเครื่อง:
  - PostgreSQL: 15432
  - Redis: 16379
  - MinIO API: 19000
  - MinIO Console: 19001
- PostgreSQL 18 ต้อง mount data ที่ `/var/lib/postgresql` ไม่ใช่ `/var/lib/postgresql/data`
- เพิ่ม `POSTGRES_SSL_MODE=disable` ใน local env เพื่อให้ config ยังเป็น fail-fast และไม่ default เงียบ
- Docker rebuild ล่าสุดเคยเจอ Docker Hub TLS handshake timeout แต่ container เดิมยัง healthy
- Redis เคย start fail เพราะรัน Compose โดยไม่มี `.env` ทำให้ `${REDIS_PASSWORD}` ว่าง; แก้ flow แล้วด้วย `make env-init`
- Fresh server bootstrap order ต้องเป็น: create/edit `.env` -> start PostgreSQL/Redis/MinIO -> run goose migrations -> start/rebuild API
- `.env.example` เป็น template เท่านั้น ส่วน runtime จริงให้ใช้ `.env` ผ่าน `make env-init`

## Current Code Conventions

- Config สำคัญต้อง fail fast หาก env missing
- ห้ามมี default เงียบ ๆ สำหรับ env สำคัญ เช่น `API_ENV`, `API_PORT`
- Query param default เช่น `page=1`, `limit=10` ยังใช้ได้
- Presenter ตอนนี้มี:
  - `RenderItem`
  - `RenderList`
  - `RenderError`
  - `ParseOffsetQuery`
  - `NewOffsetPagination`
- App runner ตอนนี้มี graceful shutdown ผ่าน signal handling
- Error handler กลาง render response เป็น `{ "error": ... }`
- `/api/v1/health/ready` ตอนนี้เช็ก API process, PostgreSQL, Redis และ MinIO
- ยังไม่เพิ่ม `custom_errors` package
- Foundation dependency clients หลักมีครบแล้ว: PostgreSQL, Redis, MinIO

## Backend Composition Rule

- `app-api/internal/bootstrap` เป็น composition root ของ backend
- ช่วง Foundation ตั้งใจให้เล็ก อย่าเพิ่ม placeholder repo/service/handler/mailer/storage/auth ก่อนมี module จริง
- เมื่อเริ่ม module ให้ wire ตามลำดับ:

```text
config
-> infrastructure clients
-> repositories
-> services/use cases
-> HTTP handlers
-> router
```

- `App` ต้องถือ long-lived resources ที่ต้อง shutdown เช่น PostgreSQL, Redis, MinIO client, worker pool และ Fiber server
- ทุก resource ที่ `App` ถือ ต้องปิดใน graceful shutdown
- GORM ใช้สำหรับ query/ORM เท่านั้น ห้ามใช้ AutoMigrate เปลี่ยน schema production ถ้ายังไม่มี migration decision ใหม่
- Schema ใช้ SQL migration ผ่าน goose
- goose CLI ใช้ผ่าน `go run github.com/pressly/goose/v3/cmd/goose@v3.27.1` และไม่เพิ่มเป็น app runtime dependency
- Primary keys ใช้ UUID v7 generated by Go application; table ใหม่ใช้ PostgreSQL `UUID` column แต่ห้ามพึ่ง database default `gen_random_uuid()` สำหรับ primary key
- JSONB fields ใน repository row model ให้ใช้ `pkg/dbtypes.JSONB` ก่อน ไม่ใช้ raw SQL/Exec เฉพาะกิจถ้า GORM `Create` ทำได้
- Timestamp สำคัญให้ repository/service set ใน Go ก่อน insert ไม่พึ่ง DB default เป็น behavior หลัก
- Auth identity แยกจาก account: `user_accounts` เป็น account owner, `auth_identities` เป็นช่องทาง login; social login ในอนาคตต้องใช้ `provider + provider_user_id`
- สำหรับย้ายขึ้น server ใหม่ ให้รัน `make env-init`, แก้ค่า `.env`, แล้วรัน `make db-migrate` ก่อน start/rebuild API สำหรับ real traffic
- Auth ยังล็อกเป็น Session-based Auth + Redis + httpOnly Cookie ไม่ใช้ JWT เป็น auth หลัก
