# Auth Login Test Examples

เอกสารนี้เป็นตัวอย่างทดสอบ backend endpoint เท่านั้น ตอนนี้ login จะสร้าง session ใน Redis และ set httpOnly cookie แต่ยังไม่มี frontend login page / auth middleware / `GET /api/v1/auth/me`

Endpoint:

```text
POST /api/v1/auth/login
```

Base URL local:

```text
http://localhost:8080
```

## Before Testing

ต้องมี account ที่ verify email แล้วก่อน:

1. สมัครด้วย `POST /api/v1/auth/register`
2. เปิด email แล้ว copy token จาก link
3. ยิง `POST /api/v1/auth/verify-email`
4. จึงค่อย login

## Behavior

เส้นนี้ใช้เข้าสู่ระบบด้วย email/password

ทำแล้ว:

- รับ email/password
- normalize email
- ตรวจ password ด้วย bcrypt
- require `auth_identities.email_verified_at`
- require `user_accounts.status = active`
- สร้าง session token แบบ random
- เก็บเฉพาะ session hash ใน `auth_sessions`
- เก็บ session record ใน Redis
- set `httpOnly` cookie ตาม `SESSION_COOKIE_NAME`
- create `auth_login_attempts`
- create `security_events`:
  - `auth.login_success`
  - `auth.login_failed`

ยังไม่ทำ:

- `GET /api/v1/auth/me`
- auth middleware ที่อ่าน cookie แล้วตรวจ Redis session
- logout/revoke session

## Success

Request:

```bash
curl -i -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -H 'User-Agent: prasankit-manual-test' \
  -d '{
    "email": "owner@example.test",
    "password": "correct-password"
  }'
```

Expected response:

```http
HTTP/1.1 200 OK
Set-Cookie: prasankit_session=<session-token>; ...
```

```json
{
  "data": {
    "account": {
      "id": "019dd18a-68e9-7393-98ea-d963c7227ae3",
      "primary_email": "owner@example.test",
      "status": "active"
    },
    "session_expires_at": "2026-04-29T12:00:00Z"
  }
}
```

Response notes:

- raw session token อยู่ใน httpOnly cookie เท่านั้น
- response body ไม่ส่ง `session_token`
- database เก็บ `session_key_hash`
- Redis เก็บ session record ด้วย key ที่อิงจาก hash

ถ้าต้องการเก็บ cookie ไว้ทดสอบเส้นถัดไป:

```bash
curl -i -c /tmp/prasankit-cookie.txt -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{
    "email": "owner@example.test",
    "password": "correct-password"
  }'
```

## Invalid Credentials

ใช้ทั้งกรณี email ไม่มีอยู่ หรือ password ไม่ถูกต้อง เพื่อไม่เปิดเผย account existence

Request:

```bash
curl -i -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{
    "email": "owner@example.test",
    "password": "wrong-password"
  }'
```

Expected response:

```http
HTTP/1.1 401 Unauthorized
```

```json
{
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "Email or password is invalid"
  }
}
```

## Email Not Verified

ถ้า account ยังไม่ได้ verify email

Expected response:

```http
HTTP/1.1 403 Forbidden
```

```json
{
  "error": {
    "code": "EMAIL_NOT_VERIFIED",
    "message": "Email is not verified"
  }
}
```

## Account Inactive

ถ้า account ถูก suspend/disabled/deleted

Expected response:

```http
HTTP/1.1 403 Forbidden
```

```json
{
  "error": {
    "code": "ACCOUNT_INACTIVE",
    "message": "Account is inactive"
  }
}
```

## Invalid JSON

Request:

```bash
curl -i -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{'
```

Expected response:

```http
HTTP/1.1 400 Bad Request
```

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Request body is invalid"
  }
}
```
