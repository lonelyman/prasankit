# Prasankit

Prasankit is a multi-tenant project/workspace management platform.

## Current Status

This repository is at the planning-to-implementation handoff stage.

The first implementation target is MVP-0:

- Auth
- Workspace registration and login
- Tenant resolution
- Project profile
- Project team
- Task board
- Basic file upload
- Basic activity log

Do not start with Finance, Deliverable, Notification, Reports, Billing, or advanced admin features until MVP-0 works end-to-end.

## Main Stack

- Frontend: Next.js 16.x, React 19.x, TypeScript 6.x
- Backend: Go 1.26.x, Fiber v3.x
- ORM / Driver: GORM v2, pgx v5
- Database: PostgreSQL 18.x
- Cache / Session: Redis 8.x
- Object Storage: MinIO
- Reverse Proxy: Traefik 3.6.x
- Deployment: Docker Compose on Ubuntu Server 24.04 LTS

## Local Dev Bootstrap

Create runtime env and start the current backend foundation:

```bash
make env-init
make dev-up
```

This starts PostgreSQL, Redis, and MinIO, runs goose migrations, starts the API, then checks `/api/v1/health/ready`.

For a new server, use the same order:

```text
env -> infrastructure -> migrations -> API -> health check
```

`.env.example` is only a template. Runtime services read `.env`, which is intentionally ignored by git.

## Architecture Rules

- Multi-tenant architecture uses shared database + tenant_id.
- tenant_id must be resolved by backend Tenant Context.
- Frontend must not send tenant_id as a trusted value.
- Workspace API must not include tenant_id in URL.
- API prefix must be /api/v1.
- API success response must use root key data.
- API error response must use root key error.
- List response must use data.items and data.pagination.
- Primary keys use UUID v7 generated by the Go application.
- All Workspace / Project APIs must pass Permission Guard.
- Files must not store full public URL in database.
- File access must go through backend permission check and signed URL.
- Auth uses Session-based Auth with Redis session store and httpOnly Cookie.
