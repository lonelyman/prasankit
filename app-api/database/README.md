# Database Migrations

Schema changes are managed with SQL migrations through goose.

GORM is used for query/ORM only. Do not use `AutoMigrate` for production schema changes.

Primary keys use PostgreSQL `UUID` columns with UUID v7 values generated by the Go application. New primary key columns should not use database-side `DEFAULT gen_random_uuid()`.

## Local Commands

Run from `app-api/`.

```bash
export PRASANKIT_DB_DSN="postgres://prasankit:change_me@localhost:15432/prasankit?sslmode=disable"

GOTOOLCHAIN=auto go run github.com/pressly/goose/v3/cmd/goose@v3.27.1 -dir database/migrations postgres "$PRASANKIT_DB_DSN" status
GOTOOLCHAIN=auto go run github.com/pressly/goose/v3/cmd/goose@v3.27.1 -dir database/migrations postgres "$PRASANKIT_DB_DSN" up
GOTOOLCHAIN=auto go run github.com/pressly/goose/v3/cmd/goose@v3.27.1 -dir database/migrations postgres "$PRASANKIT_DB_DSN" down
```

## New Server Bootstrap

For a fresh server, run migrations before starting the API for real traffic.

From the repository root:

```bash
make env-init
docker compose up -d prasankit-pgsql prasankit-redis prasankit-minio
```

Then from `app-api/`:

```bash
make db-migrate GOOSE_DSN="postgres://prasankit:change_me@localhost:15432/prasankit?sslmode=disable"
```

Then start or rebuild the API:

```bash
docker compose up -d --build prasankit-api
```

This order keeps a new install reproducible: infrastructure first, schema second, application third.

The repository root also provides a shortcut:

```bash
make dev-up
```

## Make Targets

Run from `app-api/`.

```bash
make db-migrate
make goose-status
make goose-up
make goose-down
make goose-redo
make goose-create name=create_auth_tables
```

The default `GOOSE_DSN` targets local Docker PostgreSQL on port `15432`.
